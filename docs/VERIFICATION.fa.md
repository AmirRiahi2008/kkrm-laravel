# گزارش بررسی اصلاحات رسانه و Vercel

تاریخ: ۲۰۲۶/۱۰/۲۷. سورس مبنا: `AmirRiahi2008/kkrm-laravel`، commit برابر `51a066b8e3cba1aa4564fa0fd20d6c2c2e9034ee`.

هنگام آماده‌سازی ثبت تغییرات، commit جدید `37fc3fcd0091e2a62e2254decb5807af2871545c` دریافت شد. این commit فقط ignoreهای storage و ۲۳ تصویر WebP در public/media را تغییر داده بود. اصلاحات روی همین نسخه قرار گرفتند و تمام فایل‌های جدید کاربر حفظ شدند. مسیر این ۲۳ تصویر در بکاپ SQL قبلی موجود نبود؛ بررسی فایل‌های اصلی باید با دیتابیس متناظر آن‌ها ادامه پیدا کند.

## یافته‌های قطعی

- زیر `storage` ریپازیتوری مبنا فقط ۹ فایل `.gitignore` بود و هیچ فایل رسانه‌ای در Git ثبت نشده بود. وجود عکس‌ها روی دستگاه کاربر یا هاست قبلی به معنای همراه بودنشان با clone نیست.
- جدول media در بکاپ موجود ۱۶۲ رکورد فعال داشت. هنگام بررسی در محیط تازه و بدون پوشهٔ عکس‌ها، هر ۱۶۲ فایل مفقود گزارش شدند.
- پوشهٔ resources/views در Git فقط `.gitignore` داشت؛ فایل ignore همهٔ قالب‌ها را کنار می‌گذاشت. ۳۶ قالب از نسخهٔ پیشین پروژه بازیابی شدند.
- مسیر API قبلی تصویر، برای عکس‌های خصوصی به نشست نیاز داشت اما همیشه middleware نشست را دریافت نمی‌کرد. مسیر جدید از گروه web استفاده می‌کند و کنترل دسترسی همان فایل باقی مانده است.
- استقرار قبلی storage/app را از بسته خارج می‌کرد. این رفتار برای جلوگیری از ثبت فایل‌های خصوصی در deployment باقی مانده؛ برای آپلود و رسانهٔ دائمی روی Vercel انتقال به S3 لازم است.

## بررسی‌های موفق

ساخت production دارایی‌ها با `npm ci` و `npm run build` موفق بود. همهٔ ۳۶ قالب Blade کامپایل شدند.

۵۵ بررسی یکپارچه با PHP 8.3، MySQL 8.0.46 جدا از دیتابیس اصلی، HTTP واقعی لاراول و درایور واقعی Flysystem/AWS S3 انجام شد:

- import بکاپ در MySQL و حضور ۴۱ جدول؛
- اجرای صفحات اصلی، انگلیسی، ورود، آرشیوها، کارشناسان و دانلود؛
- بارگذاری CSS و نمایش قالب‌های داشبورد؛
- خواندن تصویر کاور، تصویر داخل متن و PDF منتشرشده توسط مهمان؛
- منع دسترسی مهمان به پیش‌نویس و رسانهٔ خصوصی؛
- ورود مدیر و دریافت عکس خصوصی بدون Origin و Referer؛
- حفظ no-store برای عکس خصوصی و رد نشست منقضی‌شده از نظر session_version؛
- حفظ مسیر قدیمی رسانه و اصلاح URL دامنه‌های قبلی در HTML؛
- گزارش محل اشتباه فایل و اصلاح آن بدون حذف منبع؛
- dry run بدون تغییر فایل و دیتابیس؛
- انتقال با کنترل هش به S3، حفظ منبع و پاسخ تصویر از درایور S3؛
- منع بازنویسی فایل متفاوت مقصد، رد منبع مفقود، هش نادرست و مسیر نامعتبر؛
- دو آپلود پیاپی در داشبورد، پیش‌نمایش و منع دسترسی مهمان؛
- رد فایل جعلی تصویر و درخواست نوشتن بدون توکن CSRF؛
- قابلیت cache کردن routeها.

۳۰ بررسی دیگر برای تنظیمات استقرار انجام شد: تنظیمات معتبر، رد کلید/URL/حد حجم/endpoint نامعتبر، package discovery و cacheهای config/view/route بدون نیاز به اتصال دیتابیس در build، محل cacheهای موقت، syntax فایل‌های PHP و syntax اسکریپت شروع کانتینر.

S3 این بررسی یک شبیه‌ساز محلی پروتکل S3 بود. اطلاعات واقعی bucket، اتصال Vercel به چابوکان و نمایش فایل‌های اصلی کاربر هنوز در محیط مقصد بررسی نشده‌اند. محیط بررسی Docker daemon ندارد؛ image کامل Docker در این محیط build و اجرا نشده و هیچ deployment تازه‌ای ساخته نشده است. مراحل برنامه و دستورهای ساخت/cache به‌صورت محلی بررسی شده‌اند.

اسکریپت‌های QA و داده‌های موقت در بستهٔ پروژه قرار نگرفته‌اند. فایل‌های اصلی مفقود با دادهٔ ساختگی جایگزین نشده‌اند و هیچ تغییری در دیتابیس زندهٔ کاربر انجام نشده است.
